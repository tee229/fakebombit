## 复现与原因

在报告的751×247横屏视口中，固定1024×576画布按高度FIT后实际仅约439.7 px宽，两侧各约155 px空白。放弹直径约61.8 px、摇杆约73.9 px，正式地图高度约193 px。只需要这一视口和正常正式对局即可稳定复现，不依赖主题、皮肤或玩法种子变化。

先验证固定画布比例、控件随整体缩小、地图上下固定留白三项。主要原因是将整个桌面界面等比塞入宽屏，没有重排操作区。另发现缩放管理器父尺寸短暂滞后，以及隐藏辅助文本的静态位置导致根页面可滚动约17 px、焦点使顶部裁切，均一并修正。

## 本轮实现

- 画布逻辑宽高随安全区内的实际父容器比例变化，仍保持统一缩放，不拉伸角色或地图格子；父尺寸同步更新，并观察动态视口/方向变化。
- 手机横屏使用独立布局规则，主控件直径128 CSS px，距左右安全区边缘12 px；绘制、命中范围、摇杆归一化共用同一布局。
- 地图尽量使用上下各8 px以外的高度，完整17×15可见；左右角色卡片采用紧凑排列，地图上不添加名称或属性遮挡。
- 手机对局中只保留主控件、暂停、全屏；重试、新开、菜单、调试视图和报告可在暂停/结果页操作。暂停按钮、菜单选项和主题/皮肤选择均有至少44 px高的命中区。
- 增加用户手势触发的全屏/退出入口；旋转、父尺寸变化仍清理指针捕获和输入，不重建对局、种子或资源。全屏实际扩大多少由真机浏览器控制。
- 菜单按横屏短视口重排；尺寸缓存包括缩放和布局模式，避免同宽高比切换时沿用旧小控件。辅助文本固定在根区域内，消除焦点引起的页面滚动和裁切。
- 性能采样仍将布局更新归入表现CPU时间；新导出增加只读`presentationLayout`，便于关联复测时的控件几何。
