# #7 触屏操作与暂停恢复验证

实施日期：2026-10-14。关联 [Issue #7](https://github.com/tee229/fakebombit/issues/7)，审查基准 `6a0b3e1`。用户确认的测试边界为触屏输入输出操作意图，以及对局流程的步进、暂停和手动继续。

## 已实现

- 画布两侧分别提供四向摇杆与放弹按钮，另有暂停、重试和暂停后的继续入口；键盘仍使用 WASD / 方向键、空格、R、P / Escape、Enter。
- 独立摇杆与放弹触点可以同时操作；一次放弹动作只在首个逻辑步消费，长按与补步不重复放弹。
- 默认输入死区为摇杆半径的 20%，方向切换比例为 1.25；实际转弯继续沿用共享的中心线移动规则。两项输入设置均可配置，仍是待触屏反馈的原型值。
- 触点以 pointer ID 独立拥有；取消触摸、意外丢失捕获、暂停、缩放和场景退出清空输入及待处理动作，释放捕获。
- 浏览器失焦、隐藏及 pagehide 自动暂停。返回页面不自动继续，手动继续清空输入、补步余量和恢复首帧时间，不追赶后台时间；恢复后的表现位置保持到新逻辑步。
- Phaser 音频暂停、继续和停止接口随生命周期调用；当前无音频资源，实际音频播放尚未适用。

## 自动验证与浏览器证据

`pnpm check` 通过：8 个测试文件、145 项测试，根/核心/浏览器类型检查、架构守卫、核心及浏览器构建全部通过。Phaser 整包仍有既存的 500 kB 提示，构建成功，移动端性能验收继续由 #16 承接。

输入和对局流程的行为测试使用真实输入对象及真实对局：双指同时移动和放弹、单次动作、死区和方向稳定性、取消后的旧触点拒绝、30 / 60 / 120 FPS 一致性、暂停时全部世界冻结、清理暂停期间输入、丢弃后台时间与余量，以及终局不能继续。

实际 Codex 内置浏览器的鼠标/键盘操作完成了摇杆拖动、长按放弹、手动暂停、暂停期间方向输入无效、画布按钮继续和重试；控制台无错误。一次暂停检查的逻辑步数停在 77，方向键按住期间仍为 77。1024 × 576 画布在 1280 × 720 桌面和 844 × 390 横屏模拟视口检查了布局及按钮命中；横屏视口下画布约 693.3 × 390，暂停按钮高约 54.2 CSS 像素，放弹按钮直径约 97.5 CSS 像素。

本地截图保存在 `.scratch/issue-7-desktop-paused.png` 和 `.scratch/issue-7-mobile-landscape.png`，属于忽略的验证产物，不随代码提交。内置浏览器工具在多个标签页之间路由输入时没有触发训练场的真实 blur/visibilitychange，因此该操作不能证明实际后台生命周期；这里只记录对局流程边界的自动验证和已接入的浏览器事件。

## 待实际触屏设备验收

Issue #7 明确要求通过实际触屏检查手感和误触。当前没有已验证的物理触屏设备记录，故以下结果仍待提供，模拟视口和鼠标拖动不能替代：

- 设备型号、系统及浏览器版本、横屏尺寸。
- 两个手指同时移动与放弹，长按和连续点击不会多放弹，手指离开操作区后能正确结束。
- 触摸取消、系统手势、方向切换和转弯时不会卡住，死区与方向阈值的手感是否需要调整。
- 按住摇杆/放弹时切后台，再返回应仍暂停；继续后不补后台时间、不带回旧输入、不重复历史事件。
- 刘海与底部系统手势区内的操作可达性，以及低渲染频率下的实机体验。

在这些记录完成前，#7 保持开放。完整手机性能与体验验收仍由 #16 承接。
