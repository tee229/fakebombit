# Domain docs

This repo uses a single-context layout: `GLOSSARY.md` at the root and ADRs in `docs/adr/`.

Before exploring an area, read the glossary and any ADRs that apply. If those files do not exist yet, proceed; create them when terms or decisions are actually resolved.

Use glossary terms in issue titles, proposals, hypotheses, and tests. If a needed term is missing, reconsider the wording or note the gap for domain modeling.

If a proposal conflicts with an ADR, call out that conflict explicitly.
