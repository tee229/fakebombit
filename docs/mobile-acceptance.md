## 约定标准

正式 17×15 地图、1 对 3，使用默认 requestAnimationFrame 调度、120 秒规则时限。单局至少连续前台运行 60 秒：目标 60 FPS，平均至少 55 FPS，P95 帧间隔不超过 33 ms，无超过 200 ms 的帧间隔。首次加载、地图创建、暂停与恢复边界单独记录。不可使用 `arena`、`ai`、`seconds`、`fps`、`resourceError`、`loadDelay` 调试参数来冒充正式样本。

性能统计是更新循环间隔与 JavaScript CPU 耗时，不是 GPU 完成时间或触屏到显示的延迟。报告达标还需人工检查操作、画面、音效和设备覆盖。

## 手机步骤

1. 手机与电脑连接同一 Wi-Fi，在目标浏览器打开验收地址 `http://<电脑局域网IP>:4173/?acceptance=1&seed=issue16-baseline-c`。地址由本次本地预览提供，不是线上发布。
2. 选择本次浏览器，填写其“关于”页面的版本；设备和系统默认值来自用户提供的信息，若不符请修改。原始 UA 也会进入报告，但 Android/浏览器可能缩减 UA 信息，不能用它推断所有版本。
3. 点“返回游戏并记录”，选择糖果乐园＋薄荷兔，开始正式对局。连续前台至少 60 秒，不切后台、不暂停。若提前淘汰，重试后补测；固定种子在无操作基线中可持续60秒，可先留在出生区域观察，再检查实际操作。
4. 实际检查双指移动/放弹、转弯、拖出摇杆与触摸取消，确认横屏、系统手势区、角色、危险、通路和道具清楚。横屏对局中点暂停，再操作重试、新开和菜单；检查全屏/退出和旋转后不会保留旧按住状态。完成结果、重试、新开；再检查玩具工厂＋珊瑚机甲。第二组合需要功能/可读性检查，不强制再单独取得60秒性能样本。
5. 按住摇杆时切后台至少30秒，返回后应保持暂停；手动继续后不得自走、误放弹或追赶后台时间。检查声音暂停与恢复、切视图和重试不补播。
6. 在菜单设置页检查固定/浮动、四项独立边距和音量/粒子；局内打开设置应暂停，关闭后手动继续。浮动摇杆在左侧有效区域按下应中立，贴边中心应向内调整，拖动后四向移动，松手隐藏；双指放弹、取消、切模式/布局后不能残留输入。切明暗应联动当前主题的地图、炸弹、道具和特效，保持本局；浮动只禁用摇杆两项边距。测试较大边距后缩放/旋转，再恢复原尺寸，偏好应保留；刷新保留新设置，操作重置不动明暗/音量/粒子。
7. 在暂停或结果页点“验收报告”，亲自完成哪些项目就勾选哪些，问题写入备注。下载 JSON 并发回本对话。若不满60秒或有卡顿，也请保留并发回，不要把它勾成通过。
8. 在另两个浏览器分别重做并导出。不要刷新尚未下载的记录；页面最多保留最近12局。报告只在本页面保存，不会自动上传。

遇到无法访问：先确认相同 Wi-Fi 和电脑仍开着预览；把失败现象发回。当前未主动修改系统防火墙或开放公网端口。

## 本地启动与回归

双指断触诊断（#21）：在原地址保留已有参数并加上 `acceptance=1&touchTrace=1`。关闭表单，选择浮动摇杆并开局，复现后立即暂停、打开“验收报告”并下载 JSON。新增 `inputTrace` 只在此模式记录，最多保留最近200项指针、方向/中心变化、窗口大小、后台与焦点事件；移动事件最多每100ms一条。记录只在当前页面内存中，下载后手动提供，不自动上传。该模式不计作正式性能验收，普通 `acceptance=1` 不启用触控记录。

`pnpm test:browser-touch` 启动独立无头 Chromium 和仅绑定127.0.0.1的临时开发服务器，验证固定/浮动摇杆与放弹的原生双触点、右手松开后角色继续移动，以及真实取消清理。首次可用 `pnpm exec playwright install chromium` 安装测试浏览器；也可设置环境变量 `PLAYWRIGHT_CHANNEL=chrome` 或 `msedge` 使用已安装的浏览器，仍创建独立测试配置，不访问个人标签页。设置 `PLAYWRIGHT_BROWSER=webkit` 则用独立WebKit和1180×820平板视口（需先 `pnpm exec playwright install webkit`）；该引擎的多触点通过已固定Playwright 1.62.1的原生协议入口发送，不用DOM伪造触控。全屏兼容与失败反馈另通过能力桩验证，不冒充系统全屏测试。该检查单独运行，不加入无需浏览器的 `pnpm check`。桌面触控模拟不能替代设备复验。

2026-10-27补充：用户确认断触设备为iPad Air 8 / Safari，并报告不能全屏，系统版本待补。WebKit已复现并修复按钮层漏接松手后误清空摇杆的链路，详见[复现与修复记录](validation/issue-21-dual-touch.md)。在该iPad上复测双指及全屏；如全屏仍失败，点按后暂停下载报告，新增 `fullscreen` 保存标准/前缀能力、enabled状态和最近错误。表单可选Safari，请将型号/系统改为本次实际设备，不沿用OPPO/Android默认值。此新增目标不替代原#16的三款Android浏览器验收。

`pnpm check` 运行规则、输入、流程、资源与统计回归，并构建生产版本。随后使用 `pnpm exec vite preview --host 0.0.0.0 --port 4173` 提供仅包含生产产物的局域网预览。不要把 Vite 开发服务器当作最终性能版本。停止该进程即可停止本次预览。

`pnpm benchmark:match` 对三个正式种子测量3600步的桌面规则开销；`pnpm benchmark:match --seed=issue16-baseline-c --trace` 另生成完整世界/事件 SHA-256。trace 会增加额外内存与计算负担，其耗时不用于对比性能。基线摘要见[验收记录](validation/issue-16-mobile-acceptance.md)。

## 统计与所有权

用户确认测试边界为只读性能记录公开接口，审查基准 `05b4a4a`。`createPerformanceRecord().sample/read` 不读取系统时钟，不调用规则，不改变随机源或性能设置。报告同时保留累计诊断与 `qualification` 最长连续片段；性能判定和界面展示只使用后者，同一片段内计算时长、平均 FPS、P95 和最大帧间隔，不用其他短片段稀释失败样本。时长相同选择较新的片段。平均 FPS 使用该范围内总帧数/间隔总和，P95 使用最近秩、0.1 ms 向上取整的固定直方图；超过1000 ms的尾桶使用实际最大值作保守上界。内存固定，不保存每帧的完整世界。

每次开局/重试建立新记录。菜单、准备、暂停、后台不采样；进入/恢复后的首个间隔排除，避免把后台时间计成卡顿。连续时长在中断后重置，不能拼接多个短片段伪装60秒。预算峰值包括步数、丢弃补步时间、粒子、声音、纹理、显示对象、炸弹、危险格和 AI 公开诊断的最近查询状态数；后者不冒充一帧内全部搜索工作的总量。

新版报告为每局增加 `longFrameCount`（超过33 ms的间隔总数）和 `longFrames`（最大的20个间隔，按间隔降序，同值保留较早者）。明细包含有效采样帧号、连续片段号、片段内帧号、累计有效前台时间，以及前次/本次更新的逻辑步、规则CPU、表现CPU、补步、丢弃时间和场景计数。`intervalMs` 是进入本次更新前的间隔：应同时查看 `previousUpdate` 与 `currentUpdate`，不能只用当前补步耗时解释前面已经发生的卡顿。暂停会清空前次更新关联；恢复首帧仍只作边界，不进入长帧统计。记录只保存限量、冻结的数值证据，不保存逐帧完整世界。

这组明细供长帧定位，不参与性能判定，不因截断而删除累计卡顿次数。其计数覆盖本局所有有效片段，与最长片段的 `qualification` 范围不同。未测量的引擎渲染、浏览器调度、系统停顿等不能通过CPU差值直接归因；旧报告无法补出这些明细，首局异常需用新生产包重测。

只有 `acceptance=1` 才创建面板、读时钟和采样。面板暂停/结果入口不覆盖正式对局画面；初始表单和报告使用已有深青视觉系统。导出含设备信息、UA、静态资源路径/体积、初始化、运行统计、人工勾选和错误记录，最终验收状态始终等待人工审阅。
